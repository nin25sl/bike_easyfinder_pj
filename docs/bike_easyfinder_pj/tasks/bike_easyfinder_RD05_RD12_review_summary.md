# RD-05：画面フロー / UX

## 決定事項

- Bike EasyFinderは「検索アプリ」ではなく、ユーザー条件に応じてツーリング先を**提案するアプリ**として設計する。
- 現行の「候補一覧 → 詳細」の見せ方だけでは、提案型アプリとして弱いため再設計する。
- スポット提案は、マッチングアプリのような**カード型・逐次提案UX**を軸に再検討する。
- ユーザーが提案スポットに対して、少なくとも以下の反応を返せるようにする方向で検討する。
  - 興味あり
  - 興味なし
  - 行ったことがある
- 「興味なし」としたスポットは、以後の推薦で基本的に再表示しない方向とする。
- 「行ったことがある」は訪問済み情報として保持し、推薦に活用する。
- 「興味あり」にしたスポットを後から確認できる一覧画面・導線を設ける方向で検討する。
- 初回アクセスと2回目以降のアクセスでは、ユーザーフローが変わる前提で設計する。
- Apple Maps / Google Mapsへ遷移する前に必要なユーザー状態を保存する。

- 以下の操作後の遷移・保存仕様を決める。
  - 興味あり
  - 興味なし
  - 行ったことがある
- 「興味あり」一覧画面の要否・導線・表示内容を定義する。
- 初回起動時と2回目以降の起動時で、入力項目や省略可能項目を整理する。
- どの情報を前回値として引き継ぐか決める。

- 安全確認表示は**外部Mapへの遷移前**に行う。

   - RD-05確定後にイベントを含めて再整理。

6. **外部Map連携仕様を確定**
   - Apple Maps / Google Maps
   - 遷移方式

   - 目的地情報

7. **環境差分管理ルールを作成**
   - staging / productionは構成同一、設定差分のみ文書化。

8. **低コストMVP構成を基本設計で選定**
   - 月額1万円以内。
   - 収益化前のため、必要最小限を優先。

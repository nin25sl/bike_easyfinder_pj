# バイク目的地提案アプリ MVP テスト計画書 v1

## 1. 目的

MVPが要件定義書、基本設計書、UIデザイン案どおりに動作し、安全、プライバシー、データ品質を損なわず限定βへ進めることを確認する。本書は自動テスト、手動テスト、外部サービスを含む結合試験とリリース判定を一つの基準にまとめる。

## 2. 対象と前提

対象はiOS 17以上のiPhoneアプリ、公開API、PostgreSQLとPostGIS、データ収集Worker、Apple Maps、WeatherKit、移動時間Provider、監視・バックアップである。Android、アカウント同期、独自ナビ、リアルタイム道路規制、課金は対象外とする。

現状はiOS固定データ版とデータ収集Workerが実装済みで、公開API、S01〜S08の最終画面フロー、永続化、分析・削除、WeatherKit連携は未実装である。未実装項目の試験は対象機能の実装と同じ変更で追加し、未実施のままリリース判定を通過させない。

## 3. 品質目標

- 同一入力、同一データ版では推薦結果と順位が同じである。
- 推薦は最大5件で、全候補が利用可能時間内に収まる。
- 候補0件、外部障害、位置拒否を異なる状態として扱い、再試行または条件変更へ進める。
- S01〜S08の主要操作がVoiceOver、最大Dynamic Type、片手操作で完了できる。
- 生の現在地を保存せず、同意前イベントを送らず、削除要求をSLA内で完了する。
- 推薦APIのp95は5秒以内、候補表示成功率は95%以上、β期間の可用性は99.0%以上を目標とする。

## 4. テストレベルと実行環境

| レベル | 主対象 | 実行時期 | 合格条件 |
|---|---|---|---|
| 単体 | 時間計算、条件選択、状態遷移、スコア境界、入力検証 | 変更ごと | 全件成功 |
| Contract | OpenAPI request、response、Problem、後方互換性 | API変更ごと | スキーマ違反0件 |
| 結合 | PostGIS検索、往復ETA、イベント冪等、削除Worker、データ取込 | PRおよびstaging | 全必須ケース成功 |
| UI | S01〜S08、主要状態、VoiceOver、Dynamic Type、44pt | UI変更ごと | Severity 1・2が0件 |
| E2E | 初回、再訪、興味あり、0件、権限拒否、外部障害、ナビ失敗 | stagingとリリース候補 | 全必須シナリオ成功 |
| 非機能 | p95、レート制限、費用、ログ、バックアップ・復元 | リリース候補 | 閾値内、復元成功 |
| データ | 九州7県、重複、Freshness、Source削除、レビュー滞留 | 取込ごと、月次 | blocking違反0件 |

iOS単体・UIテストはXcode 15以降、iOS 17系の小型・標準・大型iPhone Simulatorで実行する。実機試験は九州7県ごとに最低1ケースを行う。PythonテストはPython 3.12とPostgreSQL 16、PostGISを基準とする。

## 5. 優先シナリオ

| ID | シナリオ | 期待結果 | 種別 | 自動化 |
|---|---|---|---|---|
| TP-001 | 初回起動から提案しApple Mapsへ渡す | S01、S03、S04、S05、S07の順で完了する | E2E | UI実装後 |
| TP-002 | 再訪時に前回条件で提案する | S02から1操作で提案を開始し、現在地は再取得する | E2E | UI実装後 |
| TP-003 | 興味あり一覧から出発する | 保存SpotをS06で選び、再計算後にS07へ進む | E2E | 永続化実装後 |
| TP-004 | 位置権限を拒否する | 理由、設定導線、再試行を表示し、前回位置を使わない | UI | 一部手動 |
| TP-005 | 条件に合う候補が0件 | 200と空配列を空状態で表示し、自動緩和しない | Contract・UI | API実装後 |
| TP-006 | 1件だけ経路取得に失敗する | 失敗候補を除外し、残候補と警告を表示する | 結合 | Provider実装後 |
| TP-007 | 全経路または推薦APIが失敗する | 503・504を0件と区別し、再試行と条件へ戻る操作を示す | 結合・UI | API実装後 |
| TP-008 | Apple Mapsを起動できない | 技術エラー名を出さず座標コピーを提示する | UI | 手動・UI |
| TP-009 | 最大Dynamic TypeとVoiceOverを使う | CTAが隠れず、定義済み順序で読み上げる | アクセシビリティ | 手動・UI |
| TP-010 | 分析同意を撤回して削除する | 新規送信を停止し、未送信イベントと識別子を削除する | 結合 | Privacy実装後 |
| TP-011 | 同じ条件を2回送る | 候補と順位が同じで、イベントを重複計上しない | 回帰 | 自動 |
| TP-012 | 収集元が未承認または秘密情報がない | 実行を開始せず安全なエラーを返す | 単体 | 実装済み |

## 6. 固定回帰ケース

要件定義書の固定7ケースをAPIのfixtureとして保持する。少なくとも「2時間・景色」「4時間・海・高速可」「1時間・温泉で0件」「訪問済みより未訪問を優先」「一部経路失敗」「全経路失敗」「同一入力の決定性」を含める。fixtureにはデータ版、現在地、条件、Provider応答、期待するSpot ID順、警告を記録する。

## 7. UI検証観点

- S03の時間選択は折返し可能で、興味の「おまかせ」は他選択と排他である。
- S04は一覧比較にせず1件ずつ表示し、最大5件、進捗、時間内訳、推薦理由、警告、鮮度を示す。
- リアクション後は次カードへ進み、Undoで直前状態へ戻せる。
- S05は魅力、時間、地図、根拠の順とし、天気取得失敗でも推薦・ナビを維持する。
- S06は保存時の古い所要時間を表示せず、空状態と明示的な解除操作を持つ。
- S07は安全確認後にのみApple Mapsを開き、二重操作を抑止する。
- S08の同意は任意で、破壊操作は対象と結果を確認してから実行する。
- 選択、警告、エラーを色だけに依存させず、全主要タップ領域を44pt以上にする。

## 8. データ・セキュリティ・運用試験

- 位置、イベント、installation ID、削除トークンの保存先と保持期限を確認する。
- APIエラーとログに秘密情報、正確なDB識別子、URLクエリの資格情報が出ないことを確認する。
- 未承認Source、ライセンス不明、AIのみの根拠、地域外、閉鎖、競合、重複をreadyにしない。
- 九州7県の候補数、Freshness、Source追跡、削除伝播、レビュー滞留を集計する。
- rate limit、TLS 1.2以上、最小権限、依存関係脆弱性検査を確認する。
- 日次バックアップからstagingへ復元し、RPOとRTOを記録する。
- 予算70%、90%、100%の制御と月額10,000円上限を確認する。

## 9. 不具合判定

- Severity 1: 安全上の重大事故誘発、機密情報漏えい、データ復元不能、主要機能の全面停止。
- Severity 2: 主要ユースケース不能、誤った時間内判定、削除・同意違反、回避困難なクラッシュ。
- Severity 3: 回避可能な機能不良、主要でないアクセシビリティ違反、誤解を招く表示。
- Severity 4: 軽微な表示崩れ、文言、操作感の問題。

Severity 1・2はリリース阻止とする。Severity 3は回避策、影響、修正期限を記録して判定し、Severity 4はバックログ化できる。

## 10. リリースゲート

- 固定回帰ケース、必須Contract、結合、E2Eがすべて成功している。
- Severity 1・2の未解決不具合が0件である。
- Apple Maps Provider POCと九州7県の実機ナビ引き渡しが合格している。
- VoiceOver、最大Dynamic Type、片手操作、Reduce Motionを確認済みである。
- Privacy Policy、Privacy Manifest、App Store申告、実装が一致している。
- 削除SLA、監視通知、バックアップ復元を検証済みである。
- 性能、成功率、可用性、費用が品質目標内である。

## 12. 実行コマンド

Python単体テストはリポジトリルートで次を実行する。

```powershell
.\.venv\Scripts\python.exe -m pytest data_collection/tests --basetemp .pytest-tmp
```

iOS単体テストはmacOSでプロジェクト生成後に次を実行する。Simulator名はCIの利用可能端末に合わせる。

```bash
cd ios/BikeEasyFinder
xcodegen generate
xcodebuild test -scheme BikeEasyFinder -destination 'platform=iOS Simulator,name=iPhone 15,OS=17.5'
```

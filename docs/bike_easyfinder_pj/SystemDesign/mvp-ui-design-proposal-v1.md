# バイク目的地提案アプリ MVP UIデザイン案 v1

> **目的とゴールの違い**
>
> - **目的** = Why（短時間で目的地を決められる体験を、実装可能なUIへ落とす）
> - **ゴール** = Done 条件（S01〜S08の構成と主要状態をレビューできる）

## 目次

<inline-toc preview="3"></inline-toc>

## 目的

検索結果を比較させず、利用可能時間と興味から「今の自分に合う1件」を安心して判断できるiPhone体験を設計する。

## 背景

`mvp-requirements-v1.md` では、カード型・逐次提案UX、片手操作、VoiceOver、Dynamic Type、色だけに依存しない状態表現が承認されている。一方、現状の `SearchView.swift` は候補一覧を表示し、初回・再訪・保存済み・設定の画面が未分離である。本案は要件を優先し、今後のSwiftUI実装の基準を示す。

## ゴール

- S01〜S08の画面役割、情報順序、主要CTAを確定できる。
- 初回・再訪・候補評価・詳細・外部ナビ・保存一覧の動線を確認できる。
- 正常、空、権限拒否、通信失敗、部分障害の表示方針を確認できる。
- ブランド確定前に決める事項と、実装中に検証できる事項を分離する。

## 本文

### 1. デザインコンセプト

**「迷わず、急かされず、安心して1件を選ぶ」**を中心に置く。

- 主役は地図ではなく、提案された目的地と「時間内に戻れそうか」の判断材料。
- 1画面の主要CTAは原則1つ。下部へ固定し、片手で届く位置に置く。
- 写真は期待をつくり、時間内訳・推薦理由・鮮度は意思決定を支える。
- リアクションはカードを進める操作、「ここに行く」は詳細で熟考後に選ぶ操作として分ける。
- 安全情報は常時目立たせすぎず、外部ナビ移行直前には明示的に確認する。

### 2. 視覚方針（暫定）

- **雰囲気:** 九州の自然、朝夕の空気感、ツーリング前の落ち着きを感じる、静かで実用的なトーン。
- **配色:** iOSのシステム背景を基本に、ブランド色は深い青緑を推奨。警告はSystem Orange、エラーはSystem Redを意味とアイコン・文言の併用で示す。
- **文字:** SF Pro / Dynamic Type。目的地名を最上位、合計時間を次点、推薦理由を本文として扱う。
- **形状:** 角丸はiOS標準に近い12〜16pt。操作領域は44pt以上。影は多用せず、面と余白で階層をつくる。
- **写真:** 提案カード上部に16:9または4:3の代表写真1枚。権利・鮮度・欠損時の代替表示をデータ仕様と連動させる。
- **地図:** S05に限定して判断補助として使い、カード画面では地図より目的地の魅力と時間を優先する。

ブランド色と写真方針は未決のため、本案では意味構造を優先し、色値と写真素材は確定しない。

### 3. 情報アーキテクチャ

```text
初回: S01 初回説明 → S03 条件設定 → S04 提案カード → S05 詳細 → S07 ナビ確認

再訪: S02 ホーム ┬→ 前回条件で提案 → S04
                 ├→ 条件を変更 → S03
                 ├→ S06 興味あり一覧 → S05
                 └→ S08 設定・プライバシー
```

下部タブはMVPでは採用せず、S02をハブにする。主要機能が少ない段階でタブを置くと空の階層が増えるためである。S06とS08はS02から到達させる。

### 4. 画面案

#### S01 初回説明

- **目的:** アプリの価値と責任境界を短く理解してもらう。
- **構成:** ヒーロービジュアル、見出し「今の時間にちょうどいい行き先を」、3つの説明（時間から提案／1件ずつ判断／ナビはApple Maps）、安全注記。
- **主CTA:** `はじめる`
- **補助:** Privacy Policyリンク。分析同意はここでまとめず、目的を説明できる適切なタイミングまたはS08で扱う。
- **注意:** ページング型オンボーディングは避け、1画面でスクロール可能にする。

#### S02 ホーム／提案開始

- **目的:** 再訪ユーザーが最短1タップで提案を開始できる。
- **構成:** 挨拶ではなく「今日はどれくらい走る？」、前回条件カード（時間・興味・高速）、現在地再取得の説明、保存件数。
- **主CTA:** `前回の条件で提案を受ける`
- **副CTA:** `条件を変更`、`興味ありを見る`
- **右上:** 設定ボタン。現在地は主CTA後に取得し、保存済み位置を使わない。

#### S03 提案条件

- **目的:** 必須条件を短い縦スクロールで設定する。
- **構成順:** 現在地状態 → 利用可能時間 → 興味 → 高速道路。
- **時間:** 1h / 2h / 3h / 4h / 半日 / 1日を2列または3列の選択チップで表示する。6項目を横一列のSegmented Controlにはしない。
- **興味:** taxonomy v1確定前は暫定ラベル。複数選択チップとし、`おまかせ` 選択時は他を解除する。
- **高速:** `使わない` / `使ってよい` の2択。Toggleより意図を読み取りやすい選択式を推奨する。
- **主CTA:** `この条件で提案を受ける`。必須不足時は無効化だけでなく不足項目を文言表示する。

#### S04 提案カード

- **目的:** 一覧比較なしに、1件を評価して次へ進める。
- **構成:** 進捗 `1 / 最大5件`、代表写真、目的地名、タグ、合計時間、帰着予想、推薦理由、警告・鮮度、詳細リンク。
- **時間表示:** `往復・滞在・15分の余裕込み 1時間55分` を省略せず表示する。
- **リアクション:** 下部に `興味あり`、`今回は違う`、`行ったことがある`。スワイプは補助操作に留め、必須にしない。
- **取り消し:** 操作直後にUndo付きの確認バーを表示してから次カードへ進む。
- **終了時:** 5件消化後は興味あり一覧、条件変更、同条件で再提案を提示する。

#### S05 提案詳細

- **目的:** 行く判断に必要な情報を、魅力→時間→地図→根拠の順で確認する。
- **構成:** 写真・名称、短い概要、時間内訳、地図と概要ルート、営業時間・二輪駐車等、推薦理由、出典・鮮度。
- **天気:** 天候依存Spotのみ、該当時に注意シートを初回表示し、閉じた後も本文内に注意行を残す。取得失敗時は推薦を止めず「天気情報を確認できません」を表示する。
- **主CTA:** `ここに行く` を下部固定。
- **補助:** 詳細内にも3リアクションを置けるが、主CTAより弱い表現にする。

#### S06 興味あり一覧

- **目的:** 保存した候補を後から再検討する。
- **構成:** サムネイル、名称、タグ、保存時点の合計時間ではなく現在地・条件に依存しない概要を表示する。
- **注意:** 時間は再計算前に古い値を見せない。詳細からナビへ進む場合、必要に応じて現在地と所要時間を再取得する。
- **空状態:** `まだ保存した場所はありません` と `条件を決めて提案を受ける` CTA。
- **解除:** 誤操作防止のため、行全体スワイプだけでなくメニューまたは詳細に明示ボタンを置く。

#### S07 外部ナビ確認

- **目的:** 責任境界と安全上の注意を確認してApple Mapsへ移る。
- **構成:** 目的地名、座標または簡易住所、安全確認3点（停車中に操作／現地標識を優先／Apple Mapsの最新案内を確認）。
- **天気:** S05で発火中の注意があれば1行で再掲することを推奨する。
- **主CTA:** `Apple Mapsでルートを開く`
- **副CTA:** `キャンセル`
- **失敗:** 座標コピーを提供し、技術エラー名は表示しない。

#### S08 設定・プライバシー

- **目的:** 保存状態と分析データをユーザー自身で管理できる。
- **構成:** 分析同意、前回条件の消去、リアクション履歴の消去、匿名データ削除、Privacy Policy、アプリ情報。
- **破壊操作:** 確認ダイアログで対象と結果を説明する。匿名データ削除は通信失敗時に再試行導線を出す。
- **表現:** 分析同意を機能利用の必須条件に見せない。

### 5. 共通コンポーネント

- `PrimaryBottomAction`: Safe Area上に置く下部固定の主CTA。
- `ChoiceChip`: 時間・興味・高速可否に使う。選択状態は色、チェック、アクセシビリティ値で示す。
- `SpotHero`: 代表写真、名称、タグ、鮮度をまとめる。
- `TimeSummary`: 合計、帰着予想、往路・滞在・復路・余裕の内訳。
- `ReasonBlock`: 「時間内」「興味一致」など推薦根拠を短文で示す。
- `StatusNotice`: warning / error / infoをアイコン、見出し、本文、次操作で示す。
- `UndoBanner`: リアクション結果と取り消しを示す。
- `LoadingSkeleton`: 目的地名や写真を捏造せず、レイアウトだけを保持する。

### 6. 主要状態のデザイン

- **位置権限未決定:** S03の現在地行で、ボタン操作後にOS権限を要求する。
- **位置権限拒否:** 理由、`設定を開く`、`再試行`。手入力地点はMVPで追加しない。
- **候補取得中:** CTAを無効化し、進捗表示。戻る操作は許可するが重複送信しない。
- **候補0件:** 「条件に合う候補がありません」。時間・興味・高速の変更を提案し、自動緩和しない。
- **一部経路失敗:** 残った候補を表示し、小さな注意として一部候補を除外したことを示す。
- **全経路・推薦API失敗:** 0件と区別し、`再試行` と `条件へ戻る` を表示する。
- **オフライン:** 接続確認と再試行を表示し、過去結果を新しい提案として扱わない。
- **天気取得失敗:** 詳細の注意情報だけを欠損扱いとし、推薦とナビ導線は維持する。

### 7. アクセシビリティ設計

- Dynamic Type最大時は横並びリアクションを縦並びへ切り替え、CTAを隠さない。
- VoiceOverの読み上げ順は「目的地名→合計時間→帰着予想→推薦理由→警告→操作」とする。
- 写真の代替テキストは景観の要点を短く記述し、装飾画像なら読み上げ対象外にする。
- 選択チップは `selected` trait、進捗は「5件中1件目」と読み上げる。
- 警告・エラーは色だけでなくアイコン、見出し、次操作を必ず持つ。
- 主要タップ領域44pt以上、本文と背景はWCAG AA相当を最低基準とする。

### 8. 現状実装との差分

- `SearchView` の候補一覧を廃止し、S04の単一カードへ変更する。
- 初回説明をS01、再訪ホームをS02、条件設定をS03へ分離する。
- 6項目のSegmented Pickerを折返し可能なChoiceChipへ変更する。
- リアクションを詳細画面だけでなくS04の主要操作にする。
- S06、S07、S08と、Undo、保存永続化、主要例外状態を追加する。
- S05の地図・時間内訳は活用しつつ、出典・鮮度・天気注意・ナビ前確認を追加する。

### 9. 事前に決定が必要な内容

#### 承認がないと高忠実度デザインへ進めない項目

1. **ブランドの方向性**  
   推奨: 「自然・信頼・落ち着き」。深い青緑を主色とし、レーシング感の強い黒赤は避ける。決定対象はアプリ名表記、ロゴ有無、主色、語り口。
2. **Spot写真の採用可否と運用**  
   推奨: 採用する。写真なしでは提案の魅力が弱くなる。利用許諾、出典、更新、欠損時の代替画像をデータ契約に追加する。
3. **興味taxonomy v1の画面ラベル**  
   推奨: 実データ分析後に6〜8個へ絞る。確定までは仮ラベルでワイヤーフレーム検証のみ行う。
4. **リアクション後の遷移速度**  
   推奨: 即時に次カードへ進み、5秒程度のUndoを表示する。アニメーションはReduce Motionに従う。
5. **天気注意の再掲**  
   推奨: S05で詳細表示し、発火中ならS07でも要点を1行再掲する。
6. **分析同意の提示タイミング**  
   推奨: 初回説明で包括同意を迫らず、S01後または初回提案完了後に目的を説明して任意選択させ、S08で変更可能にする。

#### 実装中のプロトタイプ検証で決められる項目

- カード写真比率、余白、角丸などの詳細値。
- 時間チップの2列／3列配置。
- リアクション3ボタンの横並び／2段配置。
- S05のMapKit初期高さ。
- Undo表示時間とカード遷移アニメーション。

### 10. 推奨する次のレビュー

1. 本案の「事前に決定が必要な内容」6点を承認または変更する。
2. S01、S03、S04、S05、S07を高忠実度モックへ進める。
3. 固定ペルソナ3名で「初回提案」「前回条件で再提案」「興味ありから出発」のタスクテストを行う。
4. VoiceOver、最大Dynamic Type、片手操作、Reduce Motionをプロトタイプで確認する。
5. 承認後にSwiftUIの画面分割と状態管理設計へ反映する。

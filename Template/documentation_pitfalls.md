# 設計ドキュメントでよくある弱点（チェック）

## 目次

<inline-toc preview="3"></inline-toc>

## 正直に言うと困るポイント

### 「目的」と「ゴール」が曖昧

- **目的**は Why、**ゴール**は Done 条件に分ける。
- ここが曖昧なドキュメントは、以降の章立てごと崩れやすい。

### 「リスク」「影響範囲」が抜けている

- 運用・保守の文脈では特に致命的。想定外の障害や巻き込みで事故りやすい。

### 「未確認事項」を書く欄がない

- 未確認のまま進めると、ほぼ確実に見落としが本番に出る。

### 「やらないこと」がない

- スコープが肥大化して計画や設計が破綻する典型パターン。

## 使い方

- 新規ドキュメントを書く前に、この一覧を一度眺めて「空欄になっていないか」を確認する。
- 各テンプレ（システム計画・設計・改修・手順書）の該当セクションに、上記を埋める形で書く。
